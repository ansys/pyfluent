journal#

The operation journal: every state-changing settings call, in order.

The journal records operations (value writes, commands and object changes), not copies of the server state. It serves two purposes:

  • undo / redo of value writes, using the value read just before each write;

  • catching up a standby session that is not up to date with the active session, starting from the newest checkpoint.

class ansys.fluent.core.resilient.engine.journal.Journal(*, max_ops=10000)#

Bases: object

Ordered, bounded record of state-changing operations with undo / redo.

Parameters:
max_opsint, optional

Maximum number of operations kept. When exceeded, the oldest operations are dropped (replay from before that point is then impossible and a failover requires a newer checkpoint).
