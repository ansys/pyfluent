fields#

Public APIs for Fluent field data, reductions, and solution variables.

The field_data package provides request, response, and mesh models for retrieving data from Fluent. Reduction, SolutionVariableInfo, and SolutionVariableData provide the related post-processing APIs. The reduction and solution_variables packages also expose their abstract contracts, response containers, and user-facing validation errors.

Create this object with LiveFieldData.new_batch(). It delegates the transport operation to the AbstractFieldData implementation owned by the parent LiveFieldData, then returns a BatchFieldData from get_response().

add_requests(obj, *args)#

Add one or more field data requests to the batch queue.

Accepts requests for surface geometry, scalar fields, vector fields, or pathlines. All requested surfaces are resolved to integer IDs. Duplicate requests are ignored with a warning. This method returns self to support method chaining.

Parameters:
objSurfaceFieldDataRequest | ScalarFieldDataRequest | VectorFieldDataRequest | PathlinesFieldDataRequest

The first (required) field data request.

*argsSurfaceFieldDataRequest | ScalarFieldDataRequest | VectorFieldDataRequest | PathlinesFieldDataRequest

Additional optional field data requests.

Returns:
Batch

Returns self to allow method chaining with get_response().

Raises:
ValueError

If two pathlines requests share the same field_name.

Examples

>>> result = (
...     field_data.new_batch()
...     .add_requests(
...         ScalarFieldDataRequest(field_name="pressure", surfaces=["wall"]),
...         VectorFieldDataRequest(field_name="velocity", surfaces=["wall"]),
...     )
...     .get_response()
... )
get_response()#

Send all queued requests to Fluent and return the retrieved field data.

Executes all requests added via add_requests() in a single server call. Returns a BatchFieldData object; use its get_field_data() method to access individual field arrays by surface.

Returns:
BatchFieldData

Container holding the retrieved field data for all requested surfaces and field types.

Examples

>>> batch = field_data.new_batch()
>>> batch.add_requests(
...     ScalarFieldDataRequest(field_name="pressure", surfaces=["wall"])
... )
>>> result = batch.get_response()
>>> pressure = result.get_field_data(
...     ScalarFieldDataRequest(field_name="pressure", surfaces=["wall"])
... )

class ansys.fluent.core.fields.LiveFieldData(field_data, field_info, scheme_interpreter, get_zones_info=None)#

Bases: BaseFieldData, FieldDataSource

Primary user-facing wrapper over an AbstractFieldData service.

The field_data argument is the transport-specific service adapter. It implements AbstractFieldData and can be backed by any kind of service, such as gRPC or REST. This wrapper adds validation, surface resolution, field metadata helpers, and conversion of transport results into user-facing objects.

Use new_batch() to create a Batch for multiple requests. The batch returns a BatchFieldData response while BaseFieldData supplies the shared response extraction logic.

get_mesh(zone)#

Retrieve the computational mesh for a Fluent cell zone.

Fetches node coordinates and element connectivity from the Fluent solver for the specified zone and returns them as a Mesh object. Only cell zones are currently supported; face zones raise NotImplementedError.

Parameters:
zonestr | int

Name or integer ID of the zone to retrieve. Must be a cell zone.

Returns:
Mesh

Mesh containing all Node coordinates and Element connectivity for the zone.

Raises:
ValueError

If zone does not match any known zone name or ID.

NotImplementedError

If zone refers to a face zone.

Examples

>>> mesh = field_data.get_mesh("fluid")
>>> print(f"Nodes: {len(mesh.nodes)}, Elements: {len(mesh.elements)}")
