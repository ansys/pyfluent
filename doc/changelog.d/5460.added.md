Make resilient mode transparent via a launch flag. ``launch_fluent(...,
resilient_mode=True)`` and ``Solver.from_install(..., resilient_mode=True)`` now
return an ordinary solver whose settings tree is resilience-enabled: existing
PyFluent code (``solver.settings...`` writes and commands) transparently gains
auto-recovery from recoverable Fluent errors, automatic file checkpoints before
irreversible commands, and -- with a warm pool via ``resilient_config`` -- failover
with checkpoint replay. The session also gains ``checkpoint`` / ``undo`` / ``redo``
/ ``rewind_to`` methods. Interception happens at the settings-service layer
(``set_var`` / ``execute_cmd``), and the recoverable-error resolver now handles the
Fluent scheme paths used there (``setup/boundary-conditions/...``). The explicit
``ResilientSolver`` facade remains available for programmatic use.
