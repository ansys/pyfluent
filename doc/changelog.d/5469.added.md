Make resilient mode a reusable, product-agnostic framework. The engine (journal,
checkpoint manager, controller, interceptor, resolver, classifier, health monitor,
warm pool) no longer hard-codes any Fluent-specific behaviour; everything that
differs between products is isolated behind a single ``ResilientAdapter`` seam.
A ``FluentAdapter`` supplies the Fluent couplings (fatal ``_fluent_connection``
error state, typed settings exceptions, ``FATAL_ERROR`` event, ``launch_fluent``,
case/data file checkpoints, solver governing-model paths, and the
``Group.__getattribute__`` navigation guard), so ``resilient_mode=True`` behaves
exactly as before. Adapters are resolved **per session**, so one Python process
can drive multiple products (e.g. Fluent and CFX) with resilient mode at once.
``ResilientAdapter``, ``FluentAdapter``, ``ErrorClasses`` and ``adapter_for`` are
exported from ``ansys.fluent.core.resilient``.
