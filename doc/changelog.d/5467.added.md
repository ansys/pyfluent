Resilient mode now automatically rolls back a failed irreversible command. When a
command such as ``iterate`` fails with a non-catastrophic error, the case/data
checkpoint taken automatically just before it is reloaded, leaving the session at
the last-good state with no manual ``undo`` / ``rewind_to`` call. This is on by
default and can be disabled with
``ResilientConfig(auto_rollback_on_failed_command=False)`` to inspect or retry
manually instead.
