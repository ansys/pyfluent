Make the resilient-mode ``benign`` error category consistent. Fluent's clean
solver-stop sentinel (``RuntimeError("()")``) is now treated as a benign interrupt
*only* for an interruptible solve command (``iterate`` / ``calculate`` /
``dual_time_iterate``), matching core PyFluent, and is surfaced as a genuine error
everywhere else (for example a value set). Previously it was treated as benign in
every context, so the sentinel could be silently swallowed on a non-interruptible
operation. All call sites now classify with the same ``interruptible`` rule.
