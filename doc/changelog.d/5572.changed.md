Remove the automatic recovery of rejected settings writes from resilient mode.
Resilient mode no longer clamps out-of-range values, snaps to the nearest allowed
value, coerces types, or enables a governing model to activate an inactive
setting: a value that Fluent rejects now raises the original error unchanged, so
no modelling decision is ever made on the user's behalf. ``RecoveryPolicy``,
``ResilientConfig.allow_model_activation``, ``activation_candidates``,
``clamp_tolerance`` and ``max_resolver_attempts``, ``ActivationCandidate``, the
``ResilientRecoveryWarning``, and the ``RECOVERED`` and ``ACTIVATED`` events are
removed, along with the settings-service ``on_inactive_access`` hook. Resilient
mode keeps its non-guessing capabilities: the operation journal with undo and
redo, automatic checkpointing before irreversible commands with rollback, and
warm-standby failover. The standalone ``enable_resilient_mode`` entry point is no
longer public; request resilient mode with ``resilient_mode=True`` on a launch or
connect function instead.
