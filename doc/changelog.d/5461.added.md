Resilient mode now auto-activates inactive targets by live introspection. When a
setting is inactive because its governing model is off (for example a thermal
boundary condition while the energy model is disabled), resilient mode discovers
the responsible model empirically -- it enables each candidate model in turn,
re-checks whether the target became active, and keeps only the one that worked --
then applies the write. This also covers the case where Fluent raises
``InactiveObjectError`` client-side while navigating into an inactive branch
(``cold_inlet.thermal.temperature.value = ...``), via a guarded, reference-counted
wrapper around the settings tree's attribute access that is a no-op for
non-resilient sessions. If no model activates the target, the original error is
re-raised unchanged.
