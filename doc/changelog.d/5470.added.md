Generalize resilient-mode inactive-target recovery so it works across products.
Governing-model activation candidates may now be ``(path, value)`` pairs (not only
boolean ``enabled`` flags set to ``True``), letting a product activate a model via
a non-boolean setting -- for example CFX's
``heat_transfer_model.option = "Total Energy"``. The controller also reclassifies
an otherwise-unrecognized set failure as an inactive-target error by live
introspection (an inactive target, or a resolution that raises the product's
``InactiveObjectError``), and scheme-path resolution now tolerates inactive
sibling objects while walking the tree. The Fluent resilient-mode guided demo
(``examples/00-fluent/demo_resilient_mode.py``) gains an opt-in ``--failover``
chapter that launches a warm standby, forces a fatal crash, and shows the standby
being promoted and replaying the last checkpoint -- matching the CFX demo so both
products demonstrate the same capability set from the same engine.
