Harden the resilient runtime's file-checkpoint tier with fail-fast pre-flight
validation. A case/data write or read is a synchronous Fluent command, so a bad
target (illegal file name, missing / unwritable directory, over-long path, or --
on restore -- a missing / empty / unreadable artifact) could leave the client
blocked on a command that never returns. The write and restore paths now validate
the target locally *before* issuing the command and raise an actionable
``CheckpointError`` instead, turning a latent stall into a clear error.
