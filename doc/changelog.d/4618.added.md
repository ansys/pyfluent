Add the `ansys.framework` platform namespace stub for the componentization of PyFluent (EPIC #4618), plus report-only import-linter contracts encoding the target layer and dependency rules and an optional `grpc` install extra. Record the componentization architecture decisions (namespace, layers, dependency rules, gRPC dependency and backward-compatibility policy) in the `ansys.framework` package documentation. Add the `ansys.framework.process` process-controller contract (`ProcessLauncher`, `ProcessHandle`, `Endpoint`, `ReadinessProbe` and `wait_until_ready`), which imports only the standard library, and move the generic process helpers used by the Fluent launchers into it (`FileUpdatedProbe`, `pid_exists`, `detached_process_kwargs`, `run_cleanup_script`, `app_data_root`); the old private names remain importable from their original modules. Add a launcher base-class hierarchy: the generic `ansys.framework.process.BaseLauncher` and the Fluent `FluentLauncher`, which `StandaloneLauncher`, `DockerLauncher`, `PIMLauncher` and `SlurmLauncher` now subclass to share argument resolution, defaults, gRPC security checks and case/lightweight-mode validation. Make `ansys.framework.process` a package with `slurm` (`SlurmScheduler`, `read_job_id`) and `container` (`run_docker_container`) submodules, add `background_process_kwargs` and `child_environment`, and use them from the Slurm, container and standalone launch paths. `PortNotProvided` now lives in `execution.launcher.error_handler` and is still importable from `fluent_connection`.
