Extend resilient-mode auto-recovery to client-side value errors. Fluent raises
some errors in the Python client before the value is sent to the server -- a
``TypeError`` for a wrong value type and a ``DisallowedValuesError`` for a value
not in ``allowed_values`` are raised inside the settings tree's ``__setattr__``.
Resilient mode now catches these via a guarded, reference-counted wrapper around
``Group.__setattr__`` (a no-op for non-resilient sessions) and applies the same
live-introspection repairs -- snap to the nearest allowed value, or safely coerce a
numeric string -- then retries. Out-of-range and server-reported disallowed-value
errors continue to be handled at the settings-service layer. Adds live
(standalone) integration tests covering the clamp, nearest-allowed, and
inactive-target-activation paths, verified against Fluent 27.1.0.
